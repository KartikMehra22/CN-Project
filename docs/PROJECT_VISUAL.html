re-run needed

Asked: Only the edge may reach ports 3001 / 3002. Roll back after.

pass  in quick inet proto tcp from { EDGE, STANDBY } to any port 3002

Extension F

Something broke? Ask in this order

Follow the path of the request. The first layer that fails is the problem. Tap a step.

1NameDoes the name become an IP?
dig @<DNS_IP> app.team1.test

Times out or wrong IP → DNS: dnsmasq stopped, wrong record, wrong resolver.

bin/doctor:36scripts/checks.sh:35
2DoorCan we knock on the port?
nc -vz <EDGE_IP> 8443

Refused or timeout → nginx down, wrong port, or a firewall rule.

bin/doctor:39scripts/checks.sh:37
3IDIs the certificate trusted?
openssl s_client -connect <EDGE_IP>:8443 -servername app.team1.test -CAfile pki/ca.crt

Verify error → CA not installed, wrong SAN, expired or swapped cert.

bin/doctor:42scripts/checks.sh:38
4AnswerDoes the site reply?
curl -i https://app.team1.test:8443/api/status

502 → edge is up but both backends failed. One backend down still works (failover).

bin/doctor:68scripts/checks.sh:42

Single point of failure: the edge nginx. Our fix today is a standby edge plus a DNS cutover (manual, about one TTL). The real fix is a floating IP shared by two edges, or DNS health checks that move the record automatically.
